Millie: bringing local coding agents to everyday hardware

A complete local coding system, currently available for macOS and Linux. Our ternary mixture-of-experts model solves 56% of the software repair tasks in SWE-bench Verified. The same model processes 261 input tokens and generates 22 output tokens per second on an iPhone 17 Pro.

We’re releasing Millie, a family of highly compressed language models, together with Millie CLI, a coding agent that runs on your own computer. Open it in a project folder and ask it to explain the code, make changes, or work through a task. It can read and edit files, run commands, and use the results to decide what to do next.

Millie CLI is built for Macs with 16 GB or more of memory and gaming PCs with at least 4 GB of GPU memory and 16 GB of system RAM. The current software release is for macOS and Linux; the phone measurements show how small and fast the underlying models are.

We trained the models, built custom formats for storing their weights and low-level code for running them efficiently, and adapted the agent software that connects them to your codebase. The model files, inference runtime—the software that runs the models—and CLI are available now. CLI means command-line interface: you use this application in a terminal.

35 billion parameters, compressed for everyday hardware

Millie derives from Agents-A1, built on the Qwen3.5-35B-A3B architecture, and supports text and image input. It uses a mixture-of-experts architecture: different parts of the model, called experts, are selected to process each token, or chunk of text. Parameters, also called weights, are the numerical values a model learns during training. Each Millie model has 35 billion of them in total, but uses roughly 3 billion for each token. This reduces computation, although the other experts still need to be stored. We trained these models to retain useful coding and agent capabilities while compressing their expert weights for devices with limited memory.

We offer three versions, with different levels of compression for the weights in those selected experts: Millie-35B-A3B-7GB uses 1-bit experts, Millie-35B-A3B-9GB uses ternary experts, and Millie-35B-A3B-11GB uses 2-bit experts. These labels describe the expert weights, rather than every weight in the model. Other compressed weights use a separate 4-bit format.

In the ternary version, expert weights take one of three values: negative, zero, or positive, with a shared scale setting their magnitude. At least half the weights in each block are zero. This lets us store the expert weights using about 1.5 bits each, plus a small amount of extra information.

Technical detail: how the ternary weights are stored

The ternary model uses a mask-and-sign encoding, with at least half the expert weights in each 256-weight block constrained to zero. A one-bit mask identifies nonzero weights, and a packed sign bit represents each nonzero value. This gives a 1.5-bit-per-weight encoding before scales; including scales and storage overhead, the format occupies approximately 1.69 bits per expert weight.

SWE-bench Verified tests whether a coding agent can fix real issues in existing software projects. It contains 500 tasks, with fixes evaluated using automated tests. Millie’s ternary model, running in our agent setup, resolved 279 of them—about 56%.

The 9GB model combines this coding capability with a small enough footprint to run on a phone. The 11GB model reaches 60.2% on SWE-bench Verified, while the 7GB model offers the smallest download and fastest phone inference in our measurements.

Fast enough to read, as well as write

A coding agent needs to read instructions, source code, and tool results before it can produce useful work. That makes input processing—prefill—an essential part of performance. We report it alongside output generation, also called decoding. We test both short inputs and longer ones; the context is the text the model has available while generating its response.

Each row below includes four measurements: reading a 512-token input, generating 128 tokens starting with an empty context, reading an entire 16,384-token input, and generating 64 tokens after reading 16,384 tokens. All speeds are in tokens per second.

Macs and gaming PCs

Millie is built for Apple silicon Macs and gaming PCs. The current release supports macOS and Linux, including settings that share work between the CPU and GPU on machines with limited GPU memory. Gaming PCs currently need to run Linux; Windows support is coming soon.

Millie’s Linux release supports NVIDIA and AMD GPUs through Vulkan, a software interface for using the GPU, with a compatible driver. The model does not have to fit entirely in GPU memory: our hybrid settings keep expert weights in the computer’s main memory and split work between the CPU and GPU.

For the 9GB and 11GB models, we provide configurations targeting GPUs with around 8 GB of dedicated memory (VRAM) using the hybrid profile, or around 4 GB using deep-hybrid, paired with 16 GB of system RAM. Context length, drivers, and other applications affect fit and performance.

We’ve tested these settings on larger NVIDIA GPUs while limiting memory use. We haven’t yet tested these profiles on physical 4 GB or 8 GB GPUs, or on AMD hardware. If you have one of these systems, we’d welcome your results, including configurations that work well and problems you encounter.

See hardware support and recommended configurations, follow the hybrid setup instructions, and share your results with your GPU, VRAM, system RAM, operating system, driver version, model, and launch settings.

From model weights to a working coding agent

Small model files also need software that can run them efficiently. Our llama.cpp fork adds support for Millie’s compressed weights and the low-level routines, called kernels, that process input and generate output efficiently. This is the runtime bundled with Millie CLI.

We adapted OpenAI Codex CLI to work with local Millie models and bundled the runtime with the agent. Millie CLI can inspect a repository, read and edit files, run commands, and iterate on a task. The release connects the model training and kernel work to something you can use directly in your own codebase.

Prebuilt packages are available for macOS on Apple silicon and Linux on x86_64. Follow the installation walkthrough, then run millie in a project directory. First launch lets you choose a model and approve its download. The model runs on your computer, with no account or API key required.

You can also run a single task from the terminal:

millie exec "Explain this codebase"

Try Millie on your own projects. If something fails, an issue with steps to reproduce it helps us improve the models, runtime, and agent.

Measurement details

Our Millie SWE-bench Verified scores report resolved tasks out of the full 500-task set. Published reference scores use their developers’ evaluation setups, linked in the table. Phone measurements are inference benchmarks, not SWE-bench runs on the phone.

Inference measurements were collected September 6, 2026 using random-token inputs. The phone and Mac benchmarks use different random-token sequences. Warmup is excluded. Phone rates average three short-context rounds and two long-context rounds; Mac rates average three repetitions per metric.

Both use four CPU threads, F16 KV caches, and Flash Attention. Phone context capacity is 16,640 tokens. The 7GB, 9GB, and 11GB phone configurations place routed experts from 0, 4, and 20 layers on CPU, respectively, with microbatches of 512, 128, and 512. Shared experts remain on GPU.

Mac microbatch size is 512 except for the 9GB model at 12 GiB pressure, which uses 128. All routed experts remain on GPU except in the 11GB model’s 12 GiB pressure run, which uses 20 CPU routed-expert layers. Each row uses one fixed configuration for all four measurements.
